## Goal

The new board carries the LSM6DSV32X; the driver component holds only the 80X. Add a 32X implementation beside the
80X behind one part-neutral public header, selected at build time, without changing healthy 80X behaviour.

## Settled design

1. Public header `imu_lsm6dsv.hpp`: vendor-neutral configuration enums, tagged FIFO word type, process functions.
   Registers, vendor enums, sensitivities and rotation layout stay private. Exactly one ST register implementation
   is linked. No runtime auto-detection, no fallback to the other chip. Keep the component directory name and the
   existing `rtos::SpiDevice` seam. Keep the old `lsm6dsv80x.hpp` names available as thin aliases for this PR so
   the superproject at the old pointer still builds (M2 moves the callers).
2. Init returns a typed status and latches readiness: wrong WHO_AM_I or a transport failure blocks configuration,
   start and every later restart. Tests: both failure modes, and that no further write or sample happens. This is
   the one intended behaviour change on the 80X (failure path only); say so in the PR.
3. Rotation word count is part of the abstraction (compile-time trait + typed decode result): 80X consumes two
   words, 32X one. Keep the 80X tag / counter checks, interleaved-temperature treatment and drop accounting.
4. 32X: restore the official ST register layer pinned by commit, with licence / source recorded
   (STMicroelectronics/lsm6dsv32x-pid, DS13511, AN6016). Audit every post-August-2025 fix of the 80X wrapper and
   carry it explicitly; do not transplant the old 32X wrapper from history and assume it is current. Rotation: x/y/z
   half floats, w reconstructed, stated reconstruction / normalisation policy, sign continuity that preserves the
   represented rotation, same output convention as the 80X path.
5. 80X baseline first, then extraction: differential synthetic coverage of old vs new 80X register transactions
   (mock SPI trace: values and order) and decoded outputs for the product configuration (120 Hz, +/-4 g, 2000 dps,
   stream FIFO, temperature, SFLP), start / stop / restart, power-down, FIFO drain / overrun, timestamps,
   temperature interleaving, rotation pairs. Share only mechanics covered by that.
6. 32X synthetic tests: identity, representative rotations, near-180-degree continuity, half-float rounding at
   norm 1, non-finite / invalid inputs, discontinuity / reset, interleaving / truncation, consumed-word count.
7. Data: synthetic inputs only. No captures, no formulas.
